# DHT ROLEPLAY

Модульный Telegram RP-бот для Car Parking Multiplayer 1. Использует Python
3.11+, aiogram 3 и SQLite. Игровые данные, заявки, каталоги, организации,
балансы и журнал операций хранятся на диске.

## Запуск

1. Установите Python 3.11 или новее.
2. В этой папке установите зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

3. Скопируйте `.env.example` в `.env`.
4. Укажите `BOT_TOKEN`, а также числовые Telegram ID администраторов в
   `ADMIN_IDS`. При необходимости задайте отдельный `OWNER_IDS`.
5. Запустите:

   ```bash
   python bot.py
   ```

База создаётся автоматически в `data/dht_roleplay.sqlite3`. Для сохранения
прогресса между перезапусками храните эту папку на постоянном диске и включите
её резервное копирование. Не добавляйте `.env` в Git и не отправляйте токен
бота в чаты или репозитории.

Для запуска в Replit задайте переменные окружения в Secrets и запускайте
`python bot.py`. Данные SQLite должны находиться на постоянном диске; удаление
файлов проекта удалит и базу.

## Команды игроков

- `/start Игровой ник | CPM ID` — регистрация.
- `/profile`, `/balance`, `/top`, `/help` — профиль, баланс, рейтинг и помощь.
- `/jobs` — список работ; `/applyjob Название` — заявка; `/myjob` — работа.
- `/work` — зарплата с настраиваемым временным ограничением.
- `/orgs`, `/joinorg Название`, `/myorg` — организации и заявки.
- `/cars`, `/businesses`, `/properties`, `/items [категория]` — каталоги.
- `/buycar ID`, `/buybusiness ID`, `/buyproperty ID`, `/buyitem ID` — покупка.
- `/mycars`, `/mybusinesses`, `/myproperties`, `/inventory` — своё имущество.
- `/collect` — получение накопившегося дохода бизнесов.
- `/pay Telegram_ID Сумма` — перевод другому игроку.

Команда регистрации принимает ник и CPM ID в одном сообщении; незавершённые
анкеты не хранятся в памяти процесса.

## Команды администраторов

Список доступен через `/adminhelp`. Он включает добавление автомобилей,
бизнесов, недвижимости, работ и товаров; изменение цен и зарплат; просмотр и
удаление каталожных записей; выдачу и снятие денег; назначение работ; блокировку
игроков; модерацию заявок; управление организациями и просмотр статистики.
Работы можно добавлять, перенастраивать и отключать; отключение снимает
назначения и закрывает ожидающие заявки. Изменения баланса проходят в
транзакциях и записываются в историю; действия администраторов записываются
в журнал.

Для каталогов используется формат с разделителем `|`, например:

```text
/addcar BMW M5 F90 | 85000 | 625 | Спортивный седан
/addbusiness Автосервис | 120000 | 4500 | Доход за сутки
/addproperty Квартира | 60000 | 0 | Жилой объект
/addjob Курьер | 2150 | civil
/additem Запчасти | Турбокомпрессор | 3000 | Деталь для тюнинга
```

Для управления кошельком:

```text
/givemoney 123456789 1000
/takemoney 123456789 500
```

Регистрируемые администраторы задаются в `ADMIN_IDS`. Только `OWNER_IDS`
(если переменная не задана, это `ADMIN_IDS`) могут использовать `/adminadd` и
`/adminremove`.

## Данные, перенесённые из старого бота

Переданный `bot(10).py` проверен: его Python-синтаксис корректен, но это единый
скрипт на 4 694 строки, который зависит от отсутствовавших в загрузке
`config.py`, `database.py` и `rp_expansion.py`. Поэтому прежние операции SQLite
и подключённый модуль расширения проверить не удалось.

Из старого файла перенесены каталоги: 140 автомобилей, 48 бизнесов, 19 объектов
недвижимости, 18 гражданских работ и 61 государственная должность. При первом
запуске они добавляются в SQLite только если соответствующих записей ещё нет;
добавленные администрацией данные и изменённые зарплаты не перезаписываются.
Также сохранены как основа профили, зарплаты, покупки, организации,
административная модерация, переводы и каталоги.

Исходный монолит сохранён в `legacy/bot_legacy_reference.py` только для
справки: он не подключён к новой точке запуска. Его криптовалюта, казино,
промокоды, налоговая система и часть RP-расширения пока не перенесены: для
последнего отсутствовал модуль, а восстановить поведение базы старой версии по
одному файлу бота нельзя.

## Расширение

Новые виды каталога добавляются в `catalog_items`, новые организации — обычными
записями в таблице `organizations`, а типы заявок централизованы в `applications`.
Это позволяет добавлять новые игровые направления без изменения модели
пользователя или схемы существующих команд.
